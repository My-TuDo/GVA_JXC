## 三、P1：上线后优先补齐

### 1. 反结账（需要产品决策）

当前只能开不能回；结账后错了只能红冲。要先定：

- 谁能反：仅 9001/8888，还是 9002 也可；
- 反到哪：只允许最近一期，还是任意已结账期；
- 后续期间已结账时如何处理；
- 快照是删除还是标记作废；
- 审计留痕字段与原因。

建议实现：`POST /jxc/period/reopen`，仅老板权限；删除/作废快照 + 写审计；
只允许“最后一个已结账期间”反结账，避免中间期空洞；补并发/权限/快照测试。

### 2. 单据状态 / Tab 聚合计数

当前单据页进入约 9~10 个 `pageSize=1` 请求。建议一个端点：

`GET /jxc/documents/counts`，一次返回 `tabs` + `statuses`；
后端 5 条 `GROUP BY status`，复用 `DocumentSearch` 过滤；
新增 5 条只读 Casbin 策略（219 → 224）；
前端删除逐状态/逐 Tab 请求，进入页降为“1 列表 + 1 counts”。

前置决策：顶部 Tab 是“全量”还是“跟随筛选”；建议跟随筛选，语义统一。

### 3. JXC Swagger / OpenAPI

当前 JXC 接口主要靠 `docs/20` 手工维护，Swagger 注释不完整；
补齐采购/销售/退货/红冲/盘点/主数据/对账/月报的注释与示例；
让前端和外部联调可以直接从 Swagger 生成类型或调试。

### 4. 可观测性与审计

- 关键写操作审计：谁、何时、对哪张单、原因；
- 慢查询日志与 P95 监控；
- 对账/月结/红冲失败告警；
- 备份恢复演练记录；
- 结构化日志字段统一（requestId、userId、docNo）。

## 四、P2：有明确触发条件再做

### 1. 多实例 + Redis

触发条件（满足任意两条）：

- 需要零停机/故障切换；
- 单实例 CPU/延迟持续压不住；
- 多门店/多副本共享对账缓存、验证码、限流；
- 需要跨实例定时任务/长任务。

届时改造：`reconcile/last` 共享缓存、定时任务 leader election、上传共享存储、
限流/验证码共享、DB 连接池重算；库存事务仍保留在 MySQL。

### 2. 模糊搜索优化

5 万条 P95 已 < 200ms；数据量继续增长再考虑前缀索引/全文索引/独立搜索。

### 3. 低库存阈值配置化

目前固定 10；后续按仓库/商品类目配置，并保留默认值。

### 4. 归档 / 分区

单据量到百万级后，按年/月归档历史账本与单据；先做只读归档，不改在线表结构。
