# AI 智能体窗口（AI 助手）实施计划

> 状态：已批准（2026-08-11）
> 决策：PC 管理端优先｜DeepSeek 官方 API｜结构化条件检索｜全库口径 + RBAC 门禁

## 一、目标

PC 管理端新增「AI 智能助手」对话窗口，两个能力：

1. **销售业绩分析**：AI 基于后端聚合数据解读销售业绩（复用现有 DashboardService，全库口径）
2. **客户需求推荐**：用户输入一段话（如"想给微胖女性推荐夏天连衣裙"）→ LLM 解析为结构化条件 → 现有商品数据检索 → LLM 生成推荐语，可一键加入收银台购物车

LLM：DeepSeek 官方 API（OpenAI 兼容 `chat/completions`，支持 SSE 流式）。

## 二、后端改动（server/）

### 1. 配置（新增 `ai` 段）

- `server/config/ai.go`：`AI{LLM: LLM{BaseURL, APIKey, Model, Timeout, MaxTokens, Temperature}}`（照 `config/mcp.go` 模式），`Server` 结构体加字段
- `server/config.yaml`：加 `ai:` 段，**apiKey 留空**，支持环境变量 `GVA_AI_APIKEY` 兜底（apiKey 不提交 git，README 说明获取方式）
- 模型默认 `deepseek-chat`，流式 `stream:true`

### 2. LLM 客户端（照 auto_code_llm.go + utils/request/http.go 模式）

- `server/service/jxc/ai_llm.go`：`type LLMClient interface` + DeepSeek 实现（`Chat(ctx, messages, jsonMode)` 同步 JSON、`ChatStream(ctx, messages)` SSE 流式，返回 `*http.Response` 直接透传给前端）
- 抽 interface 便于单测 mock；统一超时；非 2xx 转业务错误

### 3. AI Service（`server/service/jxc/ai.go`）

- `AnalyzeSales(ctx, question, days)`：调 `DashboardService` 聚合（Overview 今日/本周/本月 + Trend 近30天 + Top10 热销 + Category 占比 + StockAlert 预警数）→ 构造三层 System Prompt（角色层/硬约束层/`<data>` 数据层）→ 流式调 LLM，SSE 透传
- `RecommendGoods(ctx, demand)`：
  - 阶段 1：LLM JSON 模式解析需求 → 结构化条件 `{keywords, categoryNames, priceMin/Max, color, size}`（映射现有字段：goods.Name ILIKE、goods_category.Name、goods_sku.SalePrice/Color/Size，status=1 上架）
  - 检索：候选 SKU（LIMIT 20~30，带价格/库存/销量信号）→ 阶段 2：LLM 流式生成推荐语（每条含 SKU/价格/推荐理由）
  - 返回 `{conditions, candidates:[{skuId, skuCode, goodsName, color, size, salePrice, available, qty}]}` + 推荐语流
- **零写操作**：不提供任何写能力，只读聚合 + 只读检索

### 4. API（`server/api/v1/jxc/ai.go`，Swagger 注释完整）

- `POST /jxc/ai/analyze`：SSE 流式业绩分析（question + days）
- `POST /jxc/ai/recommend`：先返回结构化条件+候选商品 JSON，再 SSE 流式推荐语（前端分两段消费；或一次 SSE 先发 JSON 事件再发文本事件）

### 5. 路由与权限

- `server/router/jxc/ai.go`，挂 **PrivateGroup**（JWT + MustChangePwdGuard + Casbin + DataScope 全链）
- `server/source/system/`：注册 casbin api 权限点（jxc-ai-analyze / jxc-ai-recommend）+ 菜单「AI 智能助手」（jxc 分组下，图标用空心风格按 AGENT.MD 图标规范），默认授权给老板/店长角色
- 说明：AI 功能走全库口径（与看板一致），**谁能用由菜单 RBAC 门禁控制**——没分配菜单的角色看不到入口、调接口 403

### 6. 测试

- `server/service/jxc/ai_test.go`（testutil 内存库）：结构化条件解析纯函数、商品过滤检索逻辑单测；LLM 调用用 mock client
- `go vet` + `go test ./service/jxc/...` 通过

## 十、业务实现说明

### 1. 销售业绩分析（AnalyzeSales）
```
用户提问 → parseTimeRange 解析时间词（上月/上周/今年/近N天等，默认近30天）
→ buildSalesData 聚合：Overview（今日/本周/本月）+ 目标范围 Trend/Top/Category
  + 近90天按月走势 + 库存预警 + range
→ 三层系统提示词（[角色]店长朋友人设 / [说话方式] / [安全约束] + <data> 数据 + few-shot）
→ DeepSeek SSE 流式 → 后端解析增量透传 → 前端逐字渲染
```
- 口径与看板一致（全库聚合，status=2 已出库）
- 范围 ≤62 天按日趋势，更大按月（避免逐日点过多）
- AI 零写操作：只读聚合 + 只读检索

### 2. 客户需求商品推荐（RecommendGoods → RecommendStream）
```
用户输入一段需求（如"想给微胖女性推荐夏天连衣裙"）
→ 阶段1（同步）：LLM JSON 模式解析 → 结构化条件
  {keywords, categoryNames, priceMin/Max, color, size}
  （解析失败降级为空条件 → 检索全部上架热销品）
→ 检索候选 SKU：goods JOIN category/stock/sale_item，status=1 上架，
  关键词/分类/价格/颜色/尺码过滤，按近30天销量降序 LIMIT 30
→ SSE 先发 candidates 事件（条件+候选 JSON）→ 前端渲染候选卡片（可加购）
→ 阶段2（流式）：LLM 基于候选生成推荐语（markdown）逐字输出
```
- 商品无标签字段，语义匹配靠名称/款号/分类文本（一期不做 RAG，见二期方案 B）
- 加购：收银台 `aiAddToCart` 将候选 `skuId` 映射为购物车条目

### 3. 权限模型
- 接口挂 PrivateGroup 全链鉴权；**casbin 无管理员豁免**（888 也须显式授权）
- 注册走 `docs/sql/ai-register.sql`（与 pos 先例一致；曾在启动自动注册后按规范评审回退）
- 前端入口按「AI 智能助手」菜单权限显隐（menuCheck.js），无权限角色看不到按钮
- 默认授权老板 888 / 店长 9001，其他角色在「角色管理」按需分配

### 4. SSE 协议（前端解析器约束，勿破坏）
```
事件序列（recommend）：event: candidates → data: {json} → data: <文本增量>… → data: [DONE]
事件序列（analyze）：  data: <文本增量>… → data: [DONE]
```
- `event:` 行只作用于**紧随的一个** data 行（解析器已按此重置，勿改成持久事件名）
- 文本增量用**默认 message 事件**（勿写 `event: data`——曾导致文本全丢）
- message 文本**不做 JSON.parse**（独立数字 token 如 "2026" 会被误解析丢弃——已踩坑）
- 错误：命名事件 `error` 或非 SSE 响应（code≠0）统一抛错，前端显示错误消息

### 5. 历史问题记录（踩坑备忘）
| 问题 | 根因 | 修复 |
|---|---|---|
| 888 权限不足 | casbin 无管理员豁免，注册 SQL 未执行 | ai-register.sql（utf8mb4 执行） |
| SSE 无输出 | `writeSSE(c,"data",...)` 误写 `event: data` 命名事件 | 文本流不写 event 行 |
| 回答数字全消失 | 独立数字 token 被 JSON.parse 误解析丢弃 | message 事件不解析 |
| 推荐无输出 | candidates 事件后 pendingEvent 未重置 | 事件结束后重置为 message |
| 日期显示 RFC3339 | SalesHistory 缺 trimDateT（Trend 已有） | 补 trimDateT + 单测 |
| 回答模板化 | 提示词约束过密（每条带数字+先说明范围） | 重写：店长人设+松绑+few-shot |

## 八、配置说明（部署时必读）

### API Key 获取与配置

1. 在 [DeepSeek 开放平台](https://platform.deepseek.com) 注册并创建 API Key
2. 配置方式二选一（推荐环境变量，key 不入库）：
   - `config.yaml` → `ai.llm.api_key`（注意：本仓库 `config.yaml` 已被 `git update-index --skip-worktree` 标记为本地文件，不会提交，改动只在本地生效）
   - 环境变量 `GVA_AI_APIKEY`
3. 可选项：`ai.llm.model`（默认 `deepseek-chat`）、`ai.llm.temperature`、`ai.llm.timeout`、`ai.llm.max_tokens`

### 权限初始化（一次性 SQL）

首次部署需执行 `docs/sql/ai-register.sql`（幂等可重跑）：

```powershell
mysql -h127.0.0.1 -uroot -p --default-character-set=utf8mb4 gva < docs/sql/ai-register.sql
```

> ⚠️ Windows 下必须带 `--default-character-set=utf8mb4`，否则中文 description 报 `ERROR 1366`。

脚本内容：
- 注册 2 个接口到 `sys_apis`（API 管理界面可见）
- 授予老板 888 / 店长 9001 两个接口的 casbin 权限
- 创建隐藏菜单「AI 智能助手」（挂 jxc 分组下）并授权给老板/店长

> 说明：GVA 的 casbin 无管理员豁免（888 也须显式授权），本项目按 pos 扫码枪先例采用 SQL 注册，也可在「系统管理 → API 管理 / 菜单管理」界面手动配置。

其他角色如需使用，在「系统管理 → 角色管理」中给角色勾选「AI 智能助手」菜单并授权对应 API 即可。前端 AI 入口按钮按菜单权限显隐（无菜单权限的角色看不到按钮）。

### 数据口径说明

AI 业绩分析与看板同口径（全库聚合），与看板一致——「谁能用」由菜单 RBAC 门禁控制：无菜单权限的角色看不到入口，直接调接口返回 403。

### 历史数据分析（方案 A 已实施）

- `AnalyzeSales` 按问题中的时间词解析目标范围（上个月/今年/去年/近7天/近90天/本月/本周等，无时间词默认近30天），注入对应范围的趋势/热销/分类数据 + 近90天按月走势 + 概览/预警
- 范围 ≤62 天按日趋势，更大按月（避免逐日点过多）
- 经营看板「历史销售统计」选择器升级：范围精度年/月/日三级，右端点最大为今天（不允许未来）

### 二期增强（方案 B，未实施）

**AI 只读工具（function calling）**：给 LLM 挂只读工具（`sales-history` / `top` / `category` / `stock-alert`），LLM 按需调取**任意**时间范围与维度，真正"让 LLM 自己查销售单据"。仍为受控只读（参数校验 + SQL 聚合在后端），不直接暴露明细。相比方案 A：多一轮 LLM 调用，覆盖任意自定义区间（如"5月10日到6月20日"）；方案 A 先落地（词表驱动已覆盖常见问法）。

### 权限注册方式（历史决策）

初版曾实现「启动时自动幂等注册权限」，经评审回退为 **SQL 脚本注册**（与 pos 扫码枪先例一致，符合 GVA 惯例：权限变更走 SQL/界面，可审计、不被代码静默复活）。
