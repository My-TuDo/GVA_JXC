# 35-服务器部署与演示（阿里云轻量）

> 目标：个人简历长期演示站。公网可访问、数据可自愈、备案通过前只内网可达。
> 服务器：阿里云轻量，Anolis 3.2104（RHEL 8 系），2C / 1.8G 内存 / 40G 盘，x86_64。
> 相关：[`18-运行与演示`](18-运行与演示.md)、[`33-上线演示环境与验收`](33-上线演示环境与验收.md)、[`34-后端工作计划`](34-后端工作计划.md)。

---

## 一、部署形态

```
公网（阶段二）:443 → nginx（/opt/jxc/web + /api 反代）
                          └─ jxc-server 127.0.0.1:8888（GIN_MODE=release）
                               └─ MySQL 8 127.0.0.1:3306（库 jxc）
```

- **构建在本地、服务器只跑产物**：1.8G 内存跑不动 Go/Node 构建；
- 阶段一 nginx 只监听 `127.0.0.1:8080`，通过 SSH 隧道访问，公网仅开 22；
- 阶段二备案通过后改监听 80/443，绑域名上 HTTPS；
- release 模式下 `/init/*`、`/swagger` 默认不注册，nginx 再封一层。

## 二、阶段一：备案前（仅内网可达）

### 1. 本地构建

```bash
# Windows 用 Git Bash 或 WSL
bash deploy/lightweight/build.sh
```

产物在 `deploy/lightweight/dist/`：`jxc-server`（Linux amd64）与 `web-dist.tar.gz`。

### 2. 上传

```bash
scp -r deploy/lightweight root@<服务器IP>:/tmp/
scp server/config.example.yaml root@<服务器IP>:/tmp/
scp docs/sql/jxc-casbin.sql root@<服务器IP>:/tmp/
scp scripts/seed-demo.py root@<服务器IP>:/tmp/
```

### 3. 服务器初始化（一次性）

```bash
ssh root@<服务器IP>
cd /tmp/lightweight
JXC_DB_PASSWORD='数据库强密码' bash server-setup.sh
```

它会：装 nginx / mysql-server、建系统用户 `jxc` 与 `/opt/jxc` 目录、写 MySQL 调优、建库 `jxc` 与账号 `jxc@127.0.0.1`、装 nginx 与 systemd 配置。

### 4. 后端配置

```bash
install -m 640 /tmp/config.example.yaml /opt/jxc/server/config.yaml
chown jxc:jxc /opt/jxc/server/config.yaml
sed -i "s#signing-key: qmPlus#signing-key: $(openssl rand -hex 32)#" /opt/jxc/server/config.yaml
```

> 初始化阶段配置必须由 `jxc` 可写：`/init/initdb` 会把 MySQL 连接信息回写到 `config.yaml`，
> 并把 `jwt.signing-key` 重置为随机 UUID（36 位，安全）。

再手工改这几项：

```yaml
mysql:
    db-name: ""          # 首次必须为空，交给 /init/initdb 建库
    username: jxc
    password: "数据库强密码"
    path: 127.0.0.1
    port: "3306"

system:
    addr: 8888
    init-db-enable: true   # 仅首次初始化时打开

zap:
    director: log
```

> `signing-key` 必须是 32 位以上随机串；release 模式下占位值或短于 16 位会拒绝启动。

### 5. 初始化数据库

```bash
/opt/jxc/bin/upgrade.sh /tmp/lightweight/dist/jxc-server /tmp/lightweight/dist/web-dist.tar.gz
systemctl is-active jxc

curl -X POST http://127.0.0.1:8888/init/checkdb
# 期望 {"code":0,"data":{"needInit":true}}

curl -X POST http://127.0.0.1:8888/init/initdb -H 'Content-Type: application/json' -d '{
  "adminPassword":"管理员强密码","dbType":"mysql","host":"127.0.0.1",
  "port":"3306","userName":"jxc","password":"数据库强密码","dbName":"jxc"}'
```

成功后把配置交还给 root、收紧权限，再重启：

```bash
sed -i -E 's/^( *)init-db-enable: true/\1init-db-enable: false/' /opt/jxc/server/config.yaml
chown root:jxc /opt/jxc/server/config.yaml && chmod 640 /opt/jxc/server/config.yaml
systemctl restart jxc
```

### 6. 权限与角色

```bash
mysql -uroot jxc < /tmp/jxc-casbin.sql          # 219 条策略
mysql -uroot jxc < /tmp/lightweight/sql/jxc-demo-roles.sql   # 9001/9002/9003
systemctl restart jxc
```

角色说明：`9001 老板` = JXC 全量（与 888 在 JXC 内一致）、`9002 店长`、`9003 店员`、`8881 只读`（默认已有）。

### 7. 演示账号与数据

```bash
# 临时关验证码，便于脚本登录
mysql -uroot jxc -e "UPDATE sys_security_configs SET captcha_open=500 WHERE id=1"

python3 /tmp/seed-demo.py --base http://127.0.0.1:8888 \
  --password '管理员强密码' --demo-password '演示账号强密码'

# 恢复验证码（0 = 每次都要）
mysql -uroot jxc -e "UPDATE sys_security_configs SET captcha_open=0 WHERE id=1"

# 生成金库快照，供每周重置
mysqldump -uroot --single-transaction --routines --triggers jxc > /opt/jxc/backups/golden.sql
chmod 600 /opt/jxc/backups/golden.sql
```

访客统一用 `demo_boss`（老板，JXC 全量）；只读演示用 `demo_viewer`。

### 8. 访问（SSH 隧道）

```bash
# 本机执行，保持窗口开着
ssh -N -L 8080:127.0.0.1:8080 root@<服务器IP>
```

浏览器打开 `http://127.0.0.1:8080`，用 `demo_boss` 登录。

## 三、阶段二：备案通过后开放公网

1. 安全组放行 80/443（22 继续只放你的 IP）；
2. 域名解析到服务器；
3. 改 `/etc/nginx/conf.d/jxc.conf`：`listen 127.0.0.1:8080;` → `listen 80;`，并按文件末尾模板启用 443 段；
4. 证书：阿里云免费 DV 或 `acme.sh`，放到 `/etc/nginx/ssl/`；
5. `nginx -t && systemctl reload nginx`；
6. 用手机流量验证 `https://域名` 可开、登录后落 `/jxc/workspace`。

> 若暂时没有域名，也可用 `http://IP`（80 端口），但没有 HTTPS，简历链接观感较差。

## 四、日常运维

### 1. 每周重置演示数据

```cron
# root crontab -e
0 4 * * 1 /opt/jxc/bin/reset-demo.sh >> /var/log/jxc-reset.log 2>&1
```

访客有全量 JXC 权限，脏数据一定会出现；金库快照恢复是最省心的自愈方式（4 点执行，影响面最小）。

### 2. 每日备份

```cron
0 3 * * * mysqldump -uroot --single-transaction jxc | gzip > /opt/jxc/backups/jxc-$(date +\%F).sql.gz
30 3 * * * find /opt/jxc/backups -name 'jxc-*.sql.gz' -mtime +7 -delete
```

### 3. 升级

```bash
# 本地重新构建后
scp deploy/lightweight/dist/jxc-server deploy/lightweight/dist/web-dist.tar.gz root@<IP>:/tmp/
ssh root@<IP> '/opt/jxc/bin/upgrade.sh /tmp/jxc-server /tmp/web-dist.tar.gz'
```

### 4. 日志

```bash
journalctl -u jxc -n 100 --no-pager   # 服务日志
tail -f /opt/jxc/server/log/*.log     # 应用日志
tail -f /var/log/nginx/access.log
```

## 六、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 服务起不来，日志有「启动配置不安全」 | `jwt.signing-key` 是占位值或太短 | 换 32 位随机串 |
| `/init/checkdb` 连不上 | 首次 `db-name` 不为空，或 MySQL 未启动 | 按第 4 节把 `db-name` 留空 |
| 登录后所有 JXC 接口 403 | Casbin 未导入或未重启 | 第 6 节 SQL 后 `systemctl restart jxc` |
| 登录提示验证码错误 | `captcha_open=0` 表示每次都要 | 正常输入；脚本场景临时改 500 |
| 页面能开但接口 502 | 后端挂了或端口不一致 | `journalctl -u jxc`；确认 `addr: 8888` |
| 前端能开但接口 404 | nginx 未按 `/api/` 前缀反代 | 对照 `nginx-jxc.conf` |

> 安全边界：`/init` 只在首次初始化时打开，完成后必须关闭；MySQL 只监听 127.0.0.1；公网只开 22/80/443。
